How it works

工作原理：一个服务，两个壳

核心思路是把「采集」和「展示」彻底分开。采集端是一段跑在开服电脑上的 Python 脚本，展示端是同一个 HTML 文件 —— 在 Windows 上由浏览器打开，在 Android 上由 WebView 加载。两端改的只是这个 HTML 里填写的 API 地址。

01 / 采集

状态查询

用 mcstatus.JavaServer.lookup("localhost:43906") 发一次 Server List Ping，拿到 players.online / max、version.name、latency。结果缓存 5 秒，避免高频 ping 拖累服务器。

02 / 采集

日志读取与翻译

读取 logs/latest.log 的最后 80 行，按内置英译中词典逐行替换（joined the game → 加入了游戏、Can't keep up → 服务器卡顿…），长词优先匹配，避免短词覆盖长词。

03 / 服务

零框架 HTTP 接口

仅用标准库 http.server 起一个 HTTPServer，监听 0.0.0.0:8765。三个路由返回 JSON，统一带上 Access-Control-Allow-Origin: *，所以手机浏览器 / WebView 跨域也能读。

04 / 展示

一份前端，两处运行

面板是纯 HTML/CSS/JS，定时 fetch 状态与日志并渲染。本地接口 2 秒内不通时自动回退到公共查询 api.mcstatus.io；API 地址存在 localStorage，Android 端改成局域网 IP 即可远程看。

Windows 端做了什么

C# WinForms 启动器（MonitorPanel/Program.cs）编译成 4 KB 的 exe，启动后只做一件事：Process.Start 用默认浏览器打开同目录的 monitor.html。启动面板.vbs 则负责后台静默拉起 Python 服务、等 2 秒、再打开面板 —— 不弹黑窗口。

Android 端做了什么

工程 com.msll.mcpanel（compileSdk 34 / minSdk 24）里只有一个 MainActivity：创建全屏 WebView，开启 JavaScript、DOM Storage、文件访问与混合内容，然后 loadUrl("file:///android_asset/index.html")。Manifest 声明 INTERNET 权限并允许明文流量，面板才能访问 http:// 的局域网服务。

Quick start

三步跑起来

Windows

  1. 装依赖：pip install mcstatus
  2. 按上表改好 mc_server.py 里的端口与日志路径，运行 python mc_server.py，看到「MC状态服务已启动」。
  3. 双击 MC服务器监控面板.exe（或直接打开 monitor.html）；也可用 启动面板.vbs 一键静默启动。

Android

  1. 保证电脑上的服务监听 0.0.0.0:8765，且手机与电脑在同一局域网。
  2. 安装 APK，打开后点面板「设置」，把 API 地址改成 http://电脑IP:8765/status。
  3. 保存后即可看到在线人数、延迟与实时日志；本地接口不通时会自动回退到公共查询。
# 开服电脑上，一次启动本地状态服务
pip install mcstatus
python mc_server.py

# 自检：另开一个终端
curl http://localhost:8765/status
curl http://localhost:8765/logs

# 手机端填的地址（把 192.168.1.100 换成电脑实际 IP）
http://192.168.1.100:8765/status
